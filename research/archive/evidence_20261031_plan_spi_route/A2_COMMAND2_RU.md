# A2, второй проход: контракт ожидания `command2` в RM 580

Дата: 2026-11-01. Офлайн, только разбор `nvidia580-analysis.ko`. На железе ничего не запускалось.

Вопрос был: почему `command2` возвращает `0x80089010` и уходит в таймаут. Ответ найден в самом исполнителе: у него жёсткий контракт ожидания, и наблюдаемое слово под этот контракт не подходит.

## [ИЗМЕРЕНО] Код опроса

Файл `evidence_20261022_photo_followup/rm580_generic_offline/nvidia580-analysis.ko`, исполняемая секция с file offset `0x2a90`, в ней виртуальные адреса совпадают с файловыми. Функция в районе `0x12fe90`:

```
0x12ff08  cmp   ebx, 0x65
0x12ff0b  je    0x12ff3b            ; выход только по коду 0x65
0x12ff0d  mov   edx, 0x4fc          ; задержка в цикле
0x12ff12  lea   rsi, [rbp + 0x28]
0x12ff16  mov   rdi, r12
0x12ff19  call  0x12ff1e
0x12ff1e  xor   r8d, r8d
0x12ff21  mov   ecx, 0x8c040        ; чтение LINK_CONFIG_0
0x12ff26  xor   edx, edx
0x12ff28  xor   esi, esi
0x12ff2a  mov   rdi, r14
0x12ff2d  mov   ebx, eax
0x12ff2f  call  0x12ff34
0x12ff34  mov   [rbp + 0x20], eax
0x12ff37  test  al, 0x1f            ; ждём нуля в младших пяти битах
0x12ff39  jne   0x12ff08
```

Читается так: два выхода из цикла. Первый, когда младшие пять бит прочитанного слова равны нулю, тогда исполнение падает на `0x12ff3b`. Второй, когда слово целиком равно `0x65`, это единственный именованный терминальный код.

## [ВЫВОД] Почему был таймаут

Наблюдали `0x80089010`. `0x10 & 0x1f = 0x10`, то есть младшие пять бит не ноль, а до `0x65` слово не доходит. По контракту исполнителя это состояние «операция не завершена», и цикл обязан крутиться до внешнего таймаута. Это совпадает с тем, что записал тест: `status=TIMEOUT polls=40`.

То есть `0x80089010` не код ошибки. Это слово с установленным битом 4, которое железо не переводит ни в ноль, ни в `0x65`. Вопрос сузился до «кто обязан снять бит 4».

## [ИЗМЕРЕНО] Тот же контракт в MODS 520.112

Проверка на втором независимом бинарнике, `mods.unpacked` (va = file offset + `0x400000`), файловое смещение `0x1be9660`:

```
0x1be9678  cmp   ebx, 0x65
0x1be967b  je    0x1be96ad          ; тот же единственный терминальный код
0x1be9696  mov   ecx, 0x8c040
0x1be96a0  call  ...                ; чтение через обёртку
0x1be96a5  test  al, 0x1f
0x1be96ab  jne   0x1be9678          ; крутимся, пока младшие пять бит не ноль
0x1be96ad  and   eax, 0xfff3ffff    ; чистим поле скорости [19:18]
0x1be96f6  shr   eax, 0x14
0x1be96f9  and   eax, 0x3f
0x1be96fc  cmp   eax, 0x10          ; сравнение поля с 16
```

Совпадение побайтовой структуры в двух разных продуктах означает, что это конвенция NVIDIA, а не особенность нашего инструмента. Отдельный полезный штрих: в MODS поле из `0x88088` сравнивается с `0x10`, то есть с шестнадцатью, что согласуется с трактовкой этого поля как ширины.

## [ИЗМЕРЕНО] Что рядом с циклом

- перед циклом пишется `0x8b8c0` со значением `old | 4`;
- поле скорости лежит в битах `[19:18]` регистра `0x8c040`: `or r8d, 0x40000` даёт 1, `or eax, 0x80000` даёт 2, а `and eax, 0xfff3ffff` чистит оба;
- решение о скорости берётся из `0x88088` (LinkSta): `shr eax, 0x14` даёт поле `[25:20]`, ветки сравнивают его с 1, 2, 4;
- отдельно, в районе `0x12ece2`, тот же файл читает `0x88088`, берёт биты `[19:16]` как код скорости и переписывает `0x8c040` под фактическое состояние линка.

[ВЫВОД] Драйвер реактивен: он приводит `0x8c040` в соответствие с тем, что линк уже согласовал. Форсировать ширину записью в `0x8c040` он не умеет, и наш образ этого тоже не делает. Это ещё один довод в пользу того, что барьер находится в тренировке линка, а не в объявленной способности.

## [НЕИЗВЕСТНО]

1. Что означает бит 4 в `0x8c040` и кто его снимает. По этому файлу не видно писателя, который бы его гасил.
2. Что означает код `0x65`. Как enum он в разобранном участке не назван.
3. Кто выставляет бит 4 при `command2` на нашей карте. Это уже за пределами host-кода, вероятно LTSSM или PHY.

## Что это даёт

Формулировка «ширина не поднимается» перестала быть общей. Теперь есть точная развилка: либо команда ставит бит 4, и его должен снять блок тренировки линка, который на нашей карте этого не делает, либо бит 4 ставится уже после неудачной тренировки как признак отказа.

Различаются эти два случая офлайн не до конца: нужен либо потребитель бита 4, либо одно наблюдение на живой карте с чтением `0x8c040` до и после `command2` с интервалом в микросекундах. Второе дешевле, но это уже аппаратный шаг, и он не санкционирован.
