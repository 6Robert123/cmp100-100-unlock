The runtime Python source is embedded between the quoted PY_ENGINE heredoc markers in cmp100-12gb.sh. Import it with a non-__main__ module name, registered in sys.modules before exec (dataclasses).
Device, Controller, LinuxBackend, parse_csv, helper_bytes, install_plan, install_boot and main are exported. Controller.run uses backend preflight -> lock -> begin -> optional load_driver_once -> capture_protected -> [prepare, arm, bind, probe_target, wait_helper, stop_helper, target_query] -> final_query/assert_success -> cleanup -> verify_final_bindings -> unlock -> READY. Failure runs stop/cleanup and report_failure, never READY. Backend injection is an import-time test seam only; production has no environment variable that swaps hardware paths or disables checks.
Tests use an in-memory backend and temporary installer paths with fake systemctl; no helper, GPU, module or actual systemd operation runs. LinuxBackend.write additionally enforces a selected-target sysfs write allowlist. New code is present in the shell; only the historical helper's matching source is missing.
